# BUG-001 - Valid strong password is rejected during password reset

## Title

FR-03 password reset rejects a documented-valid strong password containing a special character.

## Feature

FR-03 - Forgot Password and Password Reset

## Environment

| Item | Value |
|------|-------|
| Frontend | `http://localhost:5173/forgot-password` |
| Backend | `http://localhost:3000` |
| Browser/tool | Playwright Chromium |
| Domain execution artifact | `tests/FR03/execution.md` |
| Domain raw result file | `tests/FR03/execution-results.json` |
| BVA execution artifact | `tests/FR03/execution-bva.md` |
| BVA raw result file | `tests/FR03/bva-execution-results.json` |

## Severity

High

## Preconditions

- User is unauthenticated.
- A registered account exists.
- User has successfully requested an OTP/reset token for that account.

## Steps to Reproduce

1. Open `http://localhost:5173/forgot-password`.
2. Enter the email address of an existing registered account.
3. Click `Lấy mã OTP`.
4. Confirm that the reset form appears and displays an OTP.
5. Enter the displayed OTP into `Mã OTP (4 số)`.
6. Enter `StrongPass1!` into `Mật khẩu mới`.
7. Click `Đặt lại mật khẩu`.
8. Try logging in with `StrongPass1!`.

## Expected Result

The password should be accepted because `StrongPass1!` satisfies the visible password rule:

- at least 8 characters;
- contains uppercase;
- contains lowercase;
- contains a digit;
- contains a special character.

The account password should be reset, and login with `StrongPass1!` should succeed.

## Actual Result

The UI rejects `StrongPass1!` with the alert:

`Mật khẩu quá yếu! Phải dài tối thiểu 8 ký tự, gồm chữ hoa, chữ thường, số và KÝ TỰ ĐẶC BIỆT.`

Execution also confirmed:

- login with the new password returned HTTP 401;
- login with the old password still returned HTTP 200.

Reproducible in automated execution.

- `DT-TC001`

Related failed cases masked by the same issue:

- `DT-TC006`
- `DT-TC007`
- `DT-TC008`
- `DT-TC009`

Additional BVA failures confirming the same issue:

- `BVA-TC002`: length 8 password `Aa1!aaaa` rejected.
- `BVA-TC003`: length 9 password `Aa1!aaaaa` rejected.
- `BVA-TC005`: password `Password1!` rejected with required character counts at minimum.
- `BVA-TC007`: password `PASSWORd1!` rejected with lowercase count at minimum.
- `BVA-TC009`: password `Password1!` rejected with digit count at minimum.
- `BVA-TC011`: password `Password1!` rejected with special-character count at minimum.
- `BVA-TC013`: valid issued 4-digit token plus valid length-8 password `Aa1!aaaa` rejected.

These related tests attempted to exercise token validation, but the UI rejected `StrongPass1!` before token validation could be observed.

## Impact

Users can be blocked from resetting their password even when they provide a password that satisfies the stated rule. The misleading validation also prevents reliable testing of reset-token error handling through the UI when the new password uses a normal special character.
