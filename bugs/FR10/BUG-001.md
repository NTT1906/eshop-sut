# BUG-001 - Registered User Can Update Order Status Through Admin Endpoint

## Environment

| Item | Value |
|------|-------|
| Feature | FR-10 - Order State Machine |
| Endpoint | `PUT /api/admin/orders/:id/status` |
| Backend | `http://127.0.0.1:3000` |
| Source test | `DT-TC029` |
| Repro evidence | `tests/FR10/BUG-001-repro.json` |

---

## Severity

High

An authenticated registered user can perform an admin-only order state transition. This is a privilege escalation and allows unauthorized order status modification.

---

## Preconditions

- Backend API is running.
- A normal registered user exists and can log in.
- A `pending` order exists.
- The registered user has a valid JWT token.

---

## Steps to Reproduce

1. Register and log in as a normal registered user.
2. Create an order through `POST /api/checkout`.
3. Confirm the order status is `pending`.
4. Send this request using the registered user's JWT token:

```http
PUT /api/admin/orders/<orderId>/status
Authorization: Bearer <registered-user-token>
Content-Type: application/json

{"status":"confirmed"}
```

5. Reload the order through `GET /api/orders/<orderId>`.

---

## Expected Result

The admin endpoint rejects the registered user's request.

Expected status should be HTTP 403 or another authorization failure, and the order status should remain `pending`.

---

## Actual Result

The endpoint accepts the registered user's request:

```json
{
  "status": 200,
  "body": {
    "message": "Order status updated"
  }
}
```

The order status changes from `pending` to `confirmed`.

Focused repro result:

```json
{
  "reproduced": true,
  "beforeStatus": "pending",
  "nonAdminUpdateStatus": 200,
  "afterStatus": "confirmed"
}
```

## Suggested Fix

For all `/api/admin/*` endpoints, enforce that the authenticated token belongs to a user with admin role before performing the action.

For this endpoint specifically, reject requests unless `req.user.role === "admin"` before reading or updating the order.
