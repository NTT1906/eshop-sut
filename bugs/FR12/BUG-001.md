# BUG-001 - Normal User token can access multiple Admin-only APIs

**Feature:** FR-12 - Access Control  
**Severity:** Critical  
**Status:** Reproducible  
**GitHub Issue Link:** Not created automatically; this file is a manual issue draft.

---

## Summary

A valid Normal User JWT is accepted by several Admin-only endpoints. The user can read admin user data, delete users, update order status through the admin endpoint, import products, list coupons, and create coupons.

This violates FR-12 and SEC-03: protected Admin APIs must require both a valid JWT and `role = 'admin'`.

## Preconditions

- A Normal User account exists and can log in.
- The Normal User has a valid JWT with role `user`.
- Admin-only endpoints are available.

---

## Steps to Reproduce

1. Register or use a Normal User account.
2. Log in through `POST /api/login`.
3. Copy the returned JWT.
4. Send requests with header `Authorization: Bearer <normal-user-token>`:
   - `GET /api/admin/users`
   - `DELETE /api/admin/users/:id`
   - `PUT /api/admin/orders/:id/status`
   - `POST /api/admin/import-products`
   - `GET /api/coupons`
   - `POST /api/admin/coupons`
5. Optionally place the Normal User token in `localStorage.adminToken` and open the Admin frontend.

---

## Expected Result

The system denies access with 401 or 403. No protected Admin data is returned and no protected mutation is performed.

---

## Actual Result

The API returns HTTP 200 for multiple Admin-only operations using a Normal User token. Examples from the focused repro:

| Operation | Actual Result |
|-----------|---------------|
| `GET /api/admin/users` | `200`, user list returned |
| `DELETE /api/admin/users/:id` | `200`, `{"message":"User deleted"}` |
| `PUT /api/admin/orders/:id/status` | `200`, `{"message":"Order status updated"}` |
| `POST /api/admin/import-products` | `200`, import completed |
| `GET /api/coupons` | `200`, coupon list returned |
| `POST /api/admin/coupons` | `200`, coupon created |

The Admin UI also displayed the Admin shell when a valid Normal User token was manually stored as `adminToken`.

## Recommended Fix

Enforce server-side role authorization on every Admin-only route and Admin-labeled route:

- Verify JWT validity.
- Verify token claim `role === "admin"`.
- Reject non-admin roles with 403 before executing handlers.
- Do not rely on frontend role checks as the only protection.
