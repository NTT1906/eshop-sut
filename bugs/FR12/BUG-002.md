# BUG-002 - Admin endpoint accepts non-Bearer Authorization scheme

**Feature:** FR-12 - Access Control  
**Severity:** Medium  
**Status:** Reproducible  
**GitHub Issue Link:** Not created automatically; this file is a manual issue draft.

---

## Summary

`GET /api/admin/users` accepts `Authorization: Basic <admin-token>` and returns the Admin user list. The API specification requires `Authorization: Bearer <token>`.

---

## Affected Test Case

- `DT-TC012`

---

## Environment

- Backend: `http://localhost:3000`
- Test date: 2026-07-07
- Evidence run: `tests/FR12/execution-results.json`
- Focused repro: `tests/FR12/BUG-01-repro.json`

---

## Preconditions

- Admin account exists.
- Admin can log in and obtain a valid JWT.

---

## Steps to Reproduce

1. Log in as Admin using `POST /api/login`.
2. Copy the returned JWT.
3. Send:

```http
GET /api/admin/users
Authorization: Basic <admin-jwt>
```

---

## Expected Result

The request is denied because the scheme is not `Bearer`.

---

## Actual Result

The request returns HTTP 200 and exposes the admin user list.

---

## Evidence

- Execution report: `tests/FR12/execution.md`
- Raw execution results: `tests/FR12/execution-results.json`
- Focused repro JSON: `tests/FR12/BUG-01-repro.json`
- Repro script: `playwright/repro_fr12_bugs.js`

---

## Recommended Fix

Validate the `Authorization` header format strictly:

- Require exactly `Bearer <jwt>`.
- Reject other schemes such as `Basic`.
- Reject malformed or extra-token formats before route handling.
