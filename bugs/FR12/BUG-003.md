# BUG-003 - Product and category write APIs allow non-admin or unauthenticated mutation

**Feature:** FR-12 - Access Control  
**Severity:** High  
**Status:** Reproducible  
**GitHub Issue Link:** Not created automatically; this file is a manual issue draft.

---

## Summary

Data-changing product and category APIs do not consistently require Admin authorization. A Normal User can create products and categories, and an unauthenticated request can delete a product.

This violates FR-12, which requires Admin authorization for data-changing product/category APIs.

---

## Affected Test Cases

- `DT-TC024`
- `DT-TC026`
- `DT-TC028`

---

- Backend: `http://localhost:3000`

---

## Preconditions

- A Normal User account exists and can log in.
- At least one product exists for deletion testing.

---

## Steps to Reproduce

1. Log in as a Normal User and obtain a JWT.
2. Send `POST /api/products` with a valid product body and the Normal User token.
3. Send `POST /api/categories` with a valid category body and the Normal User token.
4. Send `DELETE /api/products/:id` without any token.

---

## Expected Result

All three requests are denied with 401 or 403. No product or category is created or deleted.

---

## Actual Result

The API accepts the requests:

| Operation | Actual Result |
|-----------|---------------|
| Normal User `POST /api/products` | `200`, product created |
| No-token `DELETE /api/products/:id` | `200`, product deleted |
| Normal User `POST /api/categories` | `200`, category created |

---

## Recommended Fix

Apply shared Admin authorization middleware to all data-changing product and category endpoints:

- `POST /api/products`
- `PUT /api/products/:id`
- `DELETE /api/products/:id`
- `POST /api/categories`
- `PUT /api/categories/:id`
- `DELETE /api/categories/:id`
