# BUG-004 - Malformed JSON reaches parser before authorization on admin coupon endpoint

**Feature:** FR-12 - Access Control  
**Severity:** Medium  
**Status:** Reproducible  
**GitHub Issue Link:** Not created automatically; this file is a manual issue draft.

---

## Summary

When a Normal User sends malformed JSON to `POST /api/admin/coupons`, the API returns an HTML parser error instead of denying access first. This indicates request parsing/error handling occurs before the endpoint enforces Admin authorization.

---

## Affected Test Case

- `DT-TC036`

---

## Environment

- Backend: `http://localhost:3000`
- Test date: 2026-07-07
- Evidence run: `tests/FR12/execution-results.json`
- Focused repro: `tests/FR12/BUG-01-repro.json`

---

## Preconditions

- A Normal User account exists and can log in.
- The Normal User has a valid JWT with role `user`.

---

## Steps to Reproduce

1. Log in as a Normal User and obtain a JWT.
2. Send:

```http
POST /api/admin/coupons
Authorization: Bearer <normal-user-token>
Content-Type: application/json

{invalid-json
```

---

## Expected Result

The request is denied with 401 or 403 because the actor is not Admin. The response should not expose an HTML stack trace.

---

## Actual Result

The API returns HTTP 400 with an HTML error page containing a JSON parse stack trace.

---

## Evidence

- Execution report: `tests/FR12/execution.md`
- Raw execution results: `tests/FR12/execution-results.json`
- Focused repro JSON: `tests/FR12/BUG-01-repro.json`
- Repro script: `playwright/repro_fr12_bugs.js`

---

## Recommended Fix

- Enforce authentication/authorization before route-specific mutation logic.
- Add centralized JSON parse error handling that returns JSON, not HTML stack traces.
- Ensure non-admin actors cannot use malformed bodies to reach endpoint internals.
