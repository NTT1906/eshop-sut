# BUG-005 - Product API accepts invalid IDs and missing required body

**Feature:** FR-12 - Access Control  
**Severity:** Medium  
**Status:** Reproducible  
**GitHub Issue Link:** Not created automatically; this file is a manual issue draft.

---

## Summary

While executing FR-12 access-control cases, the product API accepted invalid product identifiers and missing required create payload fields:

- `PUT /api/products/not-a-number` returned success.
- `PUT /api/products/99999999` returned success for a nonexistent product.
- `POST /api/products` with `{}` returned success and created a product.

This is mainly a product-management/data-integrity defect, discovered during FR-12 execution because access-control tests used product write endpoints.

## Preconditions

- Admin account exists.
- Admin can log in and obtain a valid JWT.

---

## Steps to Reproduce

1. Log in as Admin and obtain a JWT.
2. Send `PUT /api/products/not-a-number` with a valid product body.
3. Send `PUT /api/products/99999999` with a valid product body.
4. Send `POST /api/products` with body `{}`.

---

## Expected Result

- Non-numeric ID should return 400 or equivalent validation error.
- Nonexistent numeric ID should return 404 and not update anything.
- Missing required product body should return 400 and not create a product.

---

## Actual Result

| Operation | Actual Result |
|-----------|---------------|
| `PUT /api/products/not-a-number` | `200`, `{"message":"Product updated"}` |
| `PUT /api/products/99999999` | `200`, `{"message":"Product updated"}` |
| `POST /api/products` with `{}` | `200`, `{"message":"Product created","id":...}` |

## Recommended Fix

- Validate `:id` path parameters before update/delete operations.
- Check affected row count for updates and return 404 when no product exists.
- Enforce required product fields before insertion.
- Return structured JSON validation errors.
